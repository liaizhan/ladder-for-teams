# Ladder for Teams

An MCP server that lets an AI assistant run a short goal-reflection exercise with each employee in private and give the team lead an anonymous summary of what blocks the team.

Only 20% of employees worldwide were engaged at work in 2025 ([Gallup, State of the Global Workplace 2026](https://www.gallup.com/workplace/349484/state-of-the-global-workplace.aspx)). Leads rarely learn what actually stops people, because people do not say it out loud. Ladder for Teams asks each person privately, gives them one concrete step for the week, and shows the lead only patterns and counts.

Built on the Ladder method by Aizhan Li, author of the Ladder method. This is a self-reflection tool. It is not therapy, diagnosis or medical advice.

**Vibe-a-thon (Geek Room x 2nd Brain Labs), Track 4: Open Innovation.** The MCP server in this repo was generated by Synapse CLI from the project's own FastAPI code.

## The problem and why Synapse fits

The Ladder logic already existed as plain Python: validation, themes, weekly steps, safety checks, storage. What was missing was a way for an agent (Claude Desktop, Cursor, Windsurf) to use it in a conversation without us writing and maintaining an MCP layer by hand.

Synapse is exactly that layer: it reads the FastAPI routes and docstrings and writes a runnable MCP server. The agent depends on these tools for every step: it cannot build a ladder, pick the weekly step or open a team report without them. When the API changes, `synapse build --discover` regenerates the tools from the code.

## How Synapse CLI was used

Synapse CLI 0.1.9 is installed locally in `node_modules` (no global install). Local Auto mode, no Synapse account and no model key needed:

```bash
npm install                     # installs @2ndbrainlabs-ai/synapse-cli locally
SYNAPSE_TELEMETRY=0 npx synapse build --local --provider ollama --auto --all-endpoints \
  --base-url http://127.0.0.1:8000 --server-name ladder-for-teams
```

The same command is available as `npm run synapse:build`. Synapse scanned `ladder_teams/api.py`, detected `python / fastapi`, extracted 5 endpoints and wrote `synapse_auto_server.py` with 5 passthrough tools:

| MCP tool | Endpoint | What it does |
| --- | --- | --- |
| `get_questions` | `GET /questions` | The four Ladder questions: goal, where you are now, blocks, fears |
| `build_member_ladder` | `POST /ladders` | Builds one employee's ladder privately, returns the reading and this week's step |
| `weekly_step_for` | `GET /teams/{team}/members/{member}/step` | This week's step, aimed at the block nearest to the person |
| `check_in` | `POST /checkins` | Records whether the step was done |
| `team_report` | `GET /teams/{team}/report` | Anonymous team report: shared kinds of blocks and progress |

`synapse analyze` requires `synapse init` with a Synapse API key, so it was not used; `build --local` runs its own scan. The scan cache Synapse wrote is in `.synapse/surface_cache.json`.

**Edited by hand (one change).** Synapse did not pass the optional `week` query parameter of `GET /teams/{team}/report` to the `team_report` tool. We added it, as Synapse allows ("Edit freely, you own this file"):

```diff
-def team_report(team: Any = None) -> dict:
+def team_report(team: Any = None, week: Any = None) -> dict:
     url = f"{os.environ["ENDPOINT_BASE_URL"]}/teams/{team}/report"
     headers = {}
-    resp = requests.get(url, headers=headers)
+    params = {"week": week} if week else None
+    resp = requests.get(url, headers=headers, params=params)
```

The tool description was extended with "Optional week like 2026-W46, default this week." Everything else in `synapse_auto_server.py` is Synapse output. Rerunning the build overwrites this edit.

## Architecture

```
Claude Desktop / Cursor (agent)
  └─ stdio ─ synapse_auto_server.py   MCP server generated by Synapse (5 tools)
       └─ HTTP ─ ladder_teams/api.py  FastAPI, 5 endpoints (what Synapse scans)
            └─ service.py             the 5 functions behind the endpoints
                 ├─ ladder.py, themes.py, safety.py   method, block themes, care checks
                 └─ store.py           SQLite (LADDER_TEAMS_DB, default ladder_teams.db)
```

## Privacy and safety

- A team report opens only when the team has at least 3 ladders, so nobody can be singled out.
- A block theme appears in the report only when at least 2 people share it. Rarer themes are hidden and only counted, so one person's block cannot be traced back to them.
- The report contains block themes (approval, time, money, skills, self-doubt, other), counts and weekly progress. People's own words are never returned to the lead.
- A person's words are stored only to give that person their own ladder and weekly step back.
- If answers mention crisis or self-harm, the tool returns a care message pointing to emergency services and a crisis line, and saves nothing. Answers about illness or symptoms get a note that the Ladder does not analyse health, and are not saved either.
- Checks are simple word lists on purpose: predictable and testable, no model in the loop.

## Quick start

Requires Python 3.12 or newer (the generated server uses PEP 701 f-strings) and, only for rebuilding the server, Node.js 20+.

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -t .      # 6 tests

.venv/bin/uvicorn ladder_teams.api:app --port 8000      # keep running
.venv/bin/python -m scripts.seed_demo                   # 2 demo teammates in team "payments"
.venv/bin/python -m scripts.mcp_demo_client             # calls the 5 tools over MCP stdio
```

`seed_demo` adds two teammates, so the third ladder built in the demo opens the team report. `mcp` is pinned below 2 because the generated server imports `mcp.server.fastmcp`.

### Connect to Claude Desktop

Settings, Developer, Edit Config, then add (use absolute paths, keep the API running):

```json
{
  "mcpServers": {
    "ladder-for-teams": {
      "command": "/absolute/path/to/ladder-for-teams/.venv/bin/python",
      "args": ["/absolute/path/to/ladder-for-teams/synapse_auto_server.py"],
      "env": { "ENDPOINT_BASE_URL": "http://127.0.0.1:8000" }
    }
  }
}
```

Restart Claude Desktop and ask, for example: "Help me build my ladder for team payments, then show the team report."

## Limitations

- English answers only for theme detection; crisis and health checks also cover a few Russian phrases. Word lists miss paraphrases and can misfire on unrelated words.
- No authentication or roles: anyone who can reach the API can read any team's report or any member's weekly step, and the member name comes from the request, so someone could add fake ladders to reach the 3-person minimum. This is a hackathon demo. In production, member identity must come from the company's SSO and the team report must be limited to that team's lead. Run it locally or behind your own auth.
- Members are plain strings; there is no user directory, and one ladder per member per team (a new one replaces the old).
- The weekly step is one fixed suggestion per theme, not personalised text.
- The generated tools take untyped arguments (`Any`), so the agent relies on tool descriptions and API validation errors.
- Rerunning `synapse build` overwrites the hand-added `week` parameter.
